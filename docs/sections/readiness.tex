\section{Readiness: predicting the trust a fit can reach}
\label{sec:ready}

The pure readiness calculation combines a supplied conditions estimate and
planned direction speeds. It computes the zero-response ceiling independently
of characterization's measured cross-response score.

\subsection{Errors and ceilings}
\label{sec:ready-sigma}

Drift error grows from the pool's unweighted mean midpoint to evaluation time;
an optional additional floor $f_e$ enters in quadrature:
\[
 \sigma_e^2=\sed^2+\bigl(\|\bm\beta\|\max(0,t_{\mathrm{now}}-
 W^{-1}\sum_w(t_{0,w}+T_w/2))\bigr)^2+f_e^2.
\]
For translation the gating error is
$\sigma_\psi=\sqrt{\sigma_{\mathrm{wave},r}^2+\sed(b_r)^2}$.
For yaw each translation channel uses
$\sigma_k=\sqrt{\sigma_{\mathrm{wave},k}^2+\sigma_e^2}$.
The service calls the ceiling calculation with zero additional gyro-bias error.
For tolerance $\tau_k$ and main speed $V$, the entry ceiling is
\[
 p_k=\operatorname{erf}\left(\frac{\tau_k|V|}{\sqrt2\sigma_k}\right)
     =2\Phi(\tau_k|V|/\sigma_k)-1,\qquad
 C_d=\prod_{k\ \mathrm{gating}}p_k,\qquad \Rgate=\min_{d\ \mathrm{planned}}C_d.
\]
A nonpositive $\sigma_k$ gives $p_k=1$. Translation has one gyro entry with
$\tau_\psi=0.015$; yaw has surge and sway entries with $\tau_\ell=0.10$.
\code{planned\_directions} uses every valid existing speed curve at the supplied
high effort, skipping missing or invalid curves. The console uses that complete
list of existing curves.

\subsection{Drift trust}
\label{sec:ready-dtrust}

With isotropic per-component drift error $\sigma_e$, the probability of a drift
error inside radius $\tau_d=0.02$\,m/s is
\[
 \Td=1-\exp\left(-\frac{\tau_d^2}{2\sigma_e^2}\right).
\]
A missing drift error returns no trust; a nonpositive error gives trust one.

\subsection{The verdict}

For measured ceiling and drift trust, grading follows the configured thresholds:
\[
 \mathrm{grade}(\Rgate,\Td)=
 \begin{cases}
 \mathrm{unknown},&\text{either measure is missing},\\
 \mathrm{poor},&\Rgate<0.60\text{ or }\Td<0.50,\\
 \mathrm{good},&\Rgate\ge0.90\text{ and }\Td\ge0.80,\\
 \mathrm{marginal},&\text{otherwise}.
 \end{cases}
\]
The pure \code{rate} checks materially trending or changed conditions first and
returns poor, even without a drift. It returns unknown without a floor or plan.
The service checks for a drift first; after a change with too few windows it
returns unknown. With a drift it checks material change before grading, and
substitutes ceiling one when no ceiling is available:
\[
 \mathrm{service}=\begin{cases}
 \mathrm{unknown},&\dhat\text{ unavailable},\\
 \mathrm{poor},&\text{material trend or change},\\
 \mathrm{grade}(C,\Td),&\text{otherwise},
 \end{cases}
 \qquad C=\begin{cases}\Rgate,&\text{ceiling available},\\1,&\text{otherwise}.\end{cases}
\]
Yaw unreliability does not reduce drift trust.

\paragraph{Procedure gates.} Health checks gate both Characterize and Physics:
poor fails, marginal warns. A health session mute skips health checks, but the
procedures also refuse a supplied poor summary directly. Characterize's
operational run is currently refused before any hold (Section~\ref{sec:thrust}),
so its conditions gate runs only in the offline path: it evaluates after the
configured initial neutral hold and records an aborted run before the holds if
poor; unknown lets that path continue. A supplied poor verdict suppresses the
tracking score. Production conditions ingestion is unwired, so these rules
require supplied conditions evidence.
